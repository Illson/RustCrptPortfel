# Личные портфели из CSV и ZIP

Импорт открывается на `/portfolios` и не требует входа. Цель — открыть несколько снимков остатков, сохранить каждый отдельно, явно подтвердить замену старого снимка и сверить количество активов по выбранным портфелям. Приложение не загружает позиции и историю операций извне. В локальном Development для их оценки доступны [живые котировки CoinGecko](live-valuation.md).

## Входные данные

- Выберите до 20 файлов CSV и ZIP за один раз. Для CSV лимит — 1 МБ и 2000 записей (включая сводку и пустые строки). Формат — UTF-8 (BOM по желанию), разделитель запятая, стандартные двойные кавычки CSV, переносы LF или CRLF.
- В ZIP должен быть ровно один файл `*_overview.csv` (или `overview.csv`). Разрешены вложенные папки. Из архива читается только этот CSV; второй файл с историей операций не распаковывается и не влияет на остатки. Лимит — 10 МБ на ZIP, 100 записей архива и 1 МБ на распакованный обзор. Повреждённый архив, обзор с паролем и архив с несколькими обзорами не импортируются.
- Нужны `Name,Amount` или `asset,quantity`; порядок столбцов не важен. Разрешены дополнительные столбцы и строки сводки перед заголовком таблицы. Поэтому файлы `*_overview.csv` с таблицей `Name` / `Amount` тоже подходят. Если в первой строке есть дата снимка в формате `YYYY-MM-DD HH:mm:ss`, она отображается как в файле (с часовым поясом, если указан).
- Количество неотрицательное, с точкой и до 96 значащих знаков после неё; допускаются разделители тысяч `,` в кавычках, например `"1,234.56"`. Нулевые позиции сохраняются; пустая таблица может обозначать пустой портфель. Отрицательные числа, дубли идентификатора в файле и ошибочные строки отклоняются.
- Необязательный `Asset ID` (`asset_id`) — устойчивый ID в формате `пространство:идентификатор`, например `chain:bitcoin`. Используйте один и тот же ID только для одного и того же актива и сети. `*_transactions.csv` содержит движения, а не остатки; такой файл не импортируется. Долларовые суммы из выгрузки игнорируются и не складываются.

## Импорт и сводка

На экране проверки у каждого файла есть свой портфель. Для ZIP предлагается имя самого архива без `.zip`, а не имя CSV внутри. По имени файла предлагается подходящий сохранённый портфель, но ничего не заменяется до подтверждения. Если файл переименован, выберите его портфель вручную. Замена обновляет весь снимок, а не прибавляет остатки. Два файла нельзя одновременно применить к одному портфелю. Файлы с ошибками отмечаются и исключаются из сохранения.

По устойчивому ID количества суммируются точно, без округления. Без ID позиции по умолчанию показаны отдельно для каждого портфеля. **Объединять по совпадающим названиям** имеет смысл только после ручной проверки, что одинаковые названия обозначают один и тот же актив. Позиции с ID и без него не смешиваются. Сводка складывает выбранные файлы, а не определяет владельца монет: не отмечайте два портфеля, в которых учтены одни и те же средства.

Хранение — в профиле браузера на текущем адресе, до 50 портфелей по 500 записей. Исходные файлы не меняются. Данные прежнего импорта не переносятся и не удаляются автоматически. Импорт, включая замену, сохраняется одной записью; ошибка проверки или записи не меняет ранее сохранённые портфели. Данные не синхронизируются между браузерами, а очистка данных сайта удалит локальную копию.
