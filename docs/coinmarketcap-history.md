# История и мониторинг CoinMarketCap

Цель: отдавать недельную историю в USD по запросу приложения, не опрашивая CoinMarketCap лишний раз. Интеграция не входит в аккаунт CoinMarketCap, не читает позиции и не меняет источник оценки портфелей.

## Внутренний API

Маршруты доступны с сессией рабочей области (сейчас — в локальном демо). Используй `slug` из `/currencies/<slug>/`, например `dash`: от 1 до 120 строчных латинских букв, цифр и дефисов, без дефиса по краям.

- `GET /api/v1/internal/market/coinmarketcap/charts/{slug}`: `200` с оригинальными `platformInfo` и `chart` в том же формате, что и CLI. Числа `chart.data.points` передаются без округления. Заголовки `X-Chart-Cache` (`refreshed`, `hit`, `stale`) и `X-Chart-Fetched-At` (ISO 8601) показывают источник ответа и время успешной загрузки.
- На новом `slug` первый вызов находит и сохраняет `cryptocurrencyId` из страницы монеты, возвращает `202` и `Retry-After`. По истечении паузы следующий вызов может взять график. Сохранённое соответствие `slug → cryptocurrencyId` используется повторно.
- Если внешняя попытка пока не разрешена, без истории API возвращает `429` с `Retry-After`. Проблемы источника без сохранённой истории дают `502` (страница монеты не найдена — `404`). Если история есть, любая задержка или ошибка обновления оставляет предыдущую версию доступной с `X-Chart-Cache: stale`. Когда есть время следующей попытки, оно указано в `X-Chart-Next-Attempt-At`.
- `GET /api/v1/internal/market/coinmarketcap/monitor`: только чтение БД, не обращается к CoinMarketCap. Возвращает срок общей паузы, состояние кэша и журнал последних 100 внешних попыток. Панель `/monitoring/coinmarketcap` показывает кэш и позволяет запросить историю вручную, а `/monitoring/coinmarketcap/requests` показывает журнал.

## Лимиты и проверка

Автоматического опроса CoinMarketCap нет: обновление происходит по обращению. После завершения каждого внешнего GET (в том числе поиска ID или неуспешного запроса) выдерживается общая пауза не менее 30 секунд. После попытки получить историю для монеты следующая попытка для того же `cryptocurrencyId` разрешена не ранее чем через час, даже если используется другой `slug`. Неудачный поиск ID также блокирует повтор на час. Успешный поиск ID — предварительный шаг, а не обновление графика. `Retry-After` от CoinMarketCap может продлить общую паузу.

Резервирование внешнего запроса и запись о его начале сохраняются в SQLite до обращения к источнику. При прерывании процесса резерв истекает, незавершённая запись помечается в журнале, а ранее сохранённая история остаётся доступна. Экземпляры API с одним файлом БД делят резерв, раздельные БД и прямые запуски диагностической CLI лимит не делят.

Критерии проверки: параллельные запросы не обходят лимит, повторное обращение отдаёт кэш, рестарт не сбрасывает лимит, сбой внешнего API не стирает историю, открытие страниц мониторинга не инициирует внешние запросы. Источник недокументирован; если CoinMarketCap изменит HTML или JSON, адаптер вернёт старую историю либо ошибку. Если провайдер изменит соответствие `slug → cryptocurrencyId`, потребуется пересмотреть кэширование этого соответствия.
