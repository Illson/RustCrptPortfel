# Тест ChatGPT: разбор монет портфеля

**Цель:** увидеть действие и короткую причину по каждой монете без чтения полного отчёта. Режим работает для одной монеты и пакета из нескольких десятков. Приложение не выполняет сделки, не подключает парсеры для аналитики, не передаёт личные остатки и не запускает обзор по расписанию.

## Запуск

1. Из корня запустите `.\local.cmd -ChatGptLab`. При необходимости добавьте `-Port 5090` (открывайте `127.0.0.1`, не `localhost` или Vite). Docker и Production не поддерживаются.
2. На `/chatgpt-lab` нажмите **Continue with ChatGPT**. В официальном окне OpenAI выберите аккаунт и разрешите приложению использовать план. Один браузерный профиль — одна привязка аккаунта/рабочего пространства в этом прототипе.
3. Выберите модель из списка аккаунта. Для одной монеты нажмите **Сформировать мнение**; необязательный баланс останется в `sessionStorage` вкладки. Для пакета выберите **Локальный портфель**, отметьте до 40 монет и нажмите **Запустить обзор портфеля**. Дубли и нулевые остатки не включаются, позиции без однозначного CoinGecko ID перечисляются отдельно. Имя портфеля, остатки и файл импорта не отправляются; каталог CoinGecko используется только для сопоставления.
4. Для отключения используйте **Отключить**. Если отзыв не подтверждён, приложение всё равно удаляет локальные токены; доступ можно проверить в [настройках ChatGPT](https://chatgpt.com/settings/usage).

## Границы теста и критерии

### Критерии качества сигнала

- Отчёт отделяет пользу держателю токена от успеха проекта, сопоставляет периоды, проверяет разовые стимулы и объясняет, почему сравнение оценки уместно. В сводке остаются действие, короткая причина и условие пересмотра.
- Только кандидаты на продажу или докупку проходят второй веб-поиск, направленный на опровержение. Без поддержки обоих ключевых утверждений и сверенных ссылок на открытые страницы итог — «Нет сигнала», а первый отчёт остаётся доступен. Ошибка квоты или подключения во втором запросе останавливает оставшуюся очередь.
- Журнал сравнивает будущие условные результаты с удержанием через 30/90 дней на одинаковом стартовом капитале. Это проверка после сигнала, не прогноз и не оценка фактического портфеля. Отсутствующие наблюдения не заменяются сегодняшней ценой; просадка учитывает только записанные точки.

- [Официальный OAuth для локальных приложений](https://developers.openai.com/siwc/token-sharing-open-source/sign-in): динамическая регистрация, callback на `127.0.0.1`, PKCE, одноразовый `state`, подпись и `nonce` ID-токена. Лаборатория слушает IPv4 loopback. Токены остаются на стороне API, файлы в `.portfel/local/chatgpt-lab/` зашифрованы через ASP.NET Data Protection с защитой ключей Windows DPAPI. `host-id` — постоянный случайный идентификатор установки, не токен. Не публикуйте файлы из `.portfel/`.
- Модели читаются из каталога аккаунта, обзор идёт только через [Responses API для ChatGPT plan](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) с веб-поиском. Оплата и квоты определяются настройками самого ChatGPT; приложение не добавляет отдельный API-ключ или другой путь оплаты. Наличие модели в каталоге не гарантирует веб-поиск. При отказе, исчерпании лимита или обрыве результат не публикуется и автоматически не повторяется.
- При сбое в карточке задания доступна **Диагностика**: код этапа, HTTP-статус, финальное событие с состоянием и причиной, если есть, и ID запроса OpenAI. В **Ответе GPT** можно увидеть до 12 000 символов текста до проверки. Полный JSON без подтверждённого завершения можно читать как **Черновик**: он помечен как непроверенный, не содержит активных ссылок и не считается опубликованным. Токены, необработанные служебные события и тела ошибок не сохраняются.
- Поток веб-поиска ограничен 16 МиБ, событие — 8 млн символов. Для публикации нужно событие `response.completed` без противоречащего статуса или причины незавершения. Если его тело не повторяет вывод, текст, результаты поиска и цитаты берутся из событий этого же потока; требования к формату поста и источникам остаются прежними.
- Первый запрос на монету: до четырёх минут, расширенный контекст `web_search`, для `gpt-6.1-terra` и `gpt-6.2-sol` — `medium` reasoning effort, для остальных — настройка провайдера. Он получает только публичный CoinGecko ID и время. Если предварительное действие — изменить позицию, повторный запрос на той же подписке (до трёх минут) получает два решающих публичных утверждения и контраргумент из первого отчёта. Повторный поиск не гарантирует точности: сервер проверяет метаданные фактически открытых страниц, а чтение и сверку содержимого выполняет GPT. В обоих запросах ссылки с параметрами, меняющими данные (например, `?type=spot`), принимаются только при совпадении с тем же вариантом в метаданных. Удаляются фрагменты, известные метки переходов (UTM, `trk=article-ssr-frontend-pulse_…`) и `highlight` на HTML-страницах `docs.dash.org`.
- Если часть ссылок не совпала, **Частичный обзор** показывает только блоки, где совпали все ссылки; вывод, контраргумент и вердикт GPT скрываются. Если не осталось ни одного блока со сверенными ссылками, полный JSON можно читать как черновик без активных ссылок. Ссылка на ту же страницу с другим параметром не подтверждает утверждение.
- По умолчанию видны **Продаём / Удерживаем / Докупаем / Нет сигнала**, короткая причина и условие пересмотра для действия. Пакет показывает число позиций по действиям, сначала продажи и докупки. Четыре блока, контраргумент, результаты второго поиска и ссылки находятся в **Аргументы и источники**. Сигнал не учитывает долю в портфеле, цену входа, налоги или индивидуальную терпимость к риску.
- **Продаём** требует двух свежих независимых неблагоприятных блоков. При «вероятно неактивен» это критические признаки и по проекту, и по споту за последние 90 дней; вывод не гарантирует, что продажа ещё возможна. **Удерживаем** требует данных по споту не старше 30 дней, продолжающейся поддержки, наблюдаемой пользы для токена и отсутствия критических признаков. **Докупаем** требует наблюдаемой пользы для токена, положительной экономики и ликвидности, данных по поддержке и предложению, отсутствия неблагоприятных сигналов и отдельного сравнения оценки не старше 14 дней со ссылками из экономики и рынков от разных издателей. Поддомены не считаются независимыми.
- Один активный запуск на браузер, пакет до 40 монет, до 50 постановок монет в часовом окне на экземпляр. Обработка последовательная. При лимите подписки или другой общей ошибке оставшиеся записи помечаются **Пропущено** без отправки. Пакет можно остановить. Очередь и результаты хранятся в памяти до перезапуска API и не попадают в учебную ленту.

### Журнал 30/90 дней

Браузер сохраняет до 300 последних сигналов с действием и котировками, без остатков, названий портфелей и исходных файлов. Записи сохраняются при перезапуске API в том же браузере и на том же адресе. Порт или очистка данных сайта меняют доступный журнал. Котировки запрашиваются через существующий публичный маршрут CoinGecko только по ID; журнал не влияет на генерацию, не передаётся в ChatGPT и не запускает фоновые задания.

- Старт фиксируется, пока открыт обзор: первая свежая котировка не ранее пяти минут до сигнала и не позднее часа после него. Давность котировки — не более 15 минут. Точки хранятся в USD с временем CoinGecko. Для контрольных дат используйте **Записать свежие котировки** в течение двух суток после 30-го и 90-го дня; между датами кнопка добавляет не более одного наблюдения за день UTC. Без снимка в нужном окне измерения нет.
- Условное сравнение на каждую монету: одинаковый стартовый капитал — одна монета и столько же в USD. Удержание ничего не меняет, продажа продаёт монету, докупка тратит свободные USD. Одна комиссия 0,10% от суммы операции (без закрывающей сделки, проскальзывания, процентов и налогов). Проценты рассчитываются из точных десятичных цен и округляются до двух знаков, ties to even. Среди снимков показывается наблюдаемая, а не максимальная внутридневная просадка; без промежуточной точки она не считается. Такой журнал не измеряет реальный результат сделок или всего портфеля.

## Внутренний HTTP-контракт

Маршруты под `/api/v1/chatgpt-lab` доступны только в описанном режиме. `GET /session` выдаёт cookie браузера, статус `not_connected` / `plan_disabled` / `connected` и `csrf_token`; все POST требуют этот токен в `X-CSRF-Token`. `POST /connect` возвращает `url` для перехода к OpenAI; `GET /callback` проверяет OAuth и возвращает браузер на страницу со статусом. `GET /models` возвращает пары `id` / `name`.

- `POST /jobs`: `{id, coin_id, model}` → `202` с заданием.
- `POST /batches`: `{id, coin_ids, model}` → `202` с массивом заданий, общим `batch_id`. `id` — UUID идемпотентности, `coin_ids` — от 1 до 40 разных публичных ID; порядок задаёт очередность. Личные поля и дубли отклоняются.
- `GET /jobs` возвращает задания только данного браузера. Статусы: `queued`, `running`, `succeeded`, `partial`, `failed`, `skipped`, `cancelled`. `decision` содержит `action` (`sell`, `hold`, `add`, `no_signal`), `reason` и `revisit` при наличии условия пересмотра. У частичных обзоров и черновиков `decision` отсутствует. `review` — только для кандидатов на продажу/докупку: `status` (`supported`, `not_supported`, `unavailable`), проверенные утверждения и метаданные ссылок или код ошибки. `completed_at` — время записи результата. `unverified_blocks` перечисляет блоки, не прошедшие сверку. `POST /batches/{id}/cancel` останавливает незавершённые задания указанного пакета. `POST /disconnect` отменяет все незавершённые задания данного браузера и возвращает `revoked`.

## Проверки

`.\local.cmd test -ChatGptLab` проверяет локальные OAuth-маршруты и интерфейс с синтетическими результатами, в том числе состав пакета и порядок рисков. [.NET-тесты](../tests/App.Tests/ChatGptLabChecks.cs) проверяют SSE, ограничение необоснованных вердиктов, очередь из 40 монет, остановку по квоте и изоляцию браузеров. Качество обзора на реальном аккаунте проверяется отдельно.
